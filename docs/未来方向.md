# 技术待优化项
- 上传失败会留下孤儿标签。
- 管理员的下架 / 恢复没有审计。
- AI 对话的上下文窗口是估值，与限频同性质。
- AI 摘要没有结果缓存。
- **旧头像清理仍缺一个前置件**：`StorageService` 没有 `list`，加它是一次需单独拍板的接口扩张。**本轮没做。**
- **`password_reset_token`的过期行清理尚未落地**
- **死信队列的监控只做了一半**。三个层次：最低是定时打日志报队列深度；中间是 `/actuator/health` 的 `HealthIndicator`（本项目**尚未引入 Actuator**）；最高是接告警通道。**孤儿对象那条死信队列已做最低一档**（`OrphanObjectDlqMonitor`，非 0 打 WARN）——不做的话投 MQ 的收益就是空的（§7.3）。
- **重置邮件那条仍是一件都没做**：它的 DLQ 非空同样需要人看，但目前只有管理台能看见。
- `IPage` 把 MyBatis-Plus 泄漏进了应用层 NoteDataAccess 和`FavoriteDataAccess`的签名里直接用了`com.baomidou.mybatisplus.core.metadata.IPage`
- `StorageService` 没有走端口 NoteService 直接注入了 jotang-storage 公共库的`StorageService` 和`OrphanObjectPublisher`
- - **用户资料缓存**：`UserProfileReader` 已走 Feign，Redis 缓存未加；笔记列表每次会批量调 user-service。

- 重建索引改为异步任务
- ai调用检索知识库工具时，因为可以调用多次工具，怎么对检索的片段去重。
