# 功能说明：登录状态校验

> **范围**：所有受保护接口（放行名单除外）· **模块**：`common`(JwtAuthFilter / JwtTokenProvider) + `config`(SecurityConfig)  
> **相关设计**：《概要设计》§6.4 认证与 JWT（D1）、§5.7 统一错误码  

---

## 1. 功能描述

无状态 JWT 方案：服务端不存会话，每个请求自带身份凭证。前端 Axios 拦截器为每个请求注入 `Authorization: Bearer <token>`，`JwtAuthFilter` 解析后把身份填进 `SecurityContext`——**只填充，不拒绝**；真正的裁决统一发生在过滤器链尾的 `AuthorizationFilter`，产出 40100 / 40300。

### 1.1 请求形态

对任意受保护接口（以笔记详情为例）：

```
GET /api/notes/123
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

两类例外：

- **放行名单**（`SecurityConfig.PUBLIC_ENDPOINTS`）：`/api/auth/register`、`/api/auth/login`、`/api/auth/password/forgot`、`/api/auth/password/reset`、`/api/colleges`，匿名即可访问；
- 其余接口一律 `anyRequest().authenticated()`，匿名即拒。

### 1.2 处理流程

```mermaid
sequenceDiagram
    autonumber
    participant C as 客户端
    participant F as JwtAuthFilter
    participant P as JwtTokenProvider
    participant CT as Controller

    Note over C: 登录成功已持有 token（见《登录》文档）
    C->>F: 请求 + Authorization: Bearer token
    F->>P: parse(token) 验签 + 解析
    alt 签名有效且未过期
        P-->>F: AuthenticatedUser(userId, username, role)
        F->>F: 包装并写入 SecurityContext<br/>role 补 ROLE_ 前缀
        F->>CT: filterChain.doFilter 放行
        Note over CT: @AuthenticationPrincipal 注入
        CT-->>C: 业务响应
    else 缺失 / 无效 / 过期
        P-->>F: 抛 JwtException
        Note over F: 仅记 debug 日志，保持匿名<br/>不在此拒绝
        F-->>C: 链尾统一拒绝 → 40100（HTTP 401）
    end
```

### 1.3 响应

| 结果 | HTTP | code | 前端动作 |
|---|---|---|---|
| 校验通过 | 200 | 0 | 正常渲染业务数据 |
| 匿名 / token 无效 / token 过期 | 401 | 40100 | 清本地 token，跳登录页 |
| 已登录但权限不足（非本人 / 非管理员） | 403 | 40300 | 提示无权限 |

### 1.4 涉及文件

| 层 | 文件 |
|---|---|
| 过滤器 | `common/JwtAuthFilter.java` |
| 令牌解析 | `common/JwtTokenProvider.java`（`parse`）· `common/AuthenticatedUser.java` |
| 安全链与裁决 | `config/SecurityConfig.java`（放行名单 · 过滤器注册 · EntryPoint / AccessDeniedHandler） |
| 错误码 | `common/ErrorCode.java`（40100 / 40300） |

## 2. 核心逻辑及说明

### 2.1 只填充、不拒绝——位置决定的纪律

`JwtAuthFilter` 被插在 `UsernamePasswordAuthenticationFilter` 之前，位于 `ExceptionTranslationFilter` **上游**。这意味着：

- 在这里抛出的异常**没人翻译**——`@RestControllerAdvice` 收不到，链上的翻译官也管不到过滤器自己抛的东西；
- 在这里手写的响应会**绕开统一响应体**。

所以无效 token 在这里只做一件事：什么都不设，请求以匿名身份继续走链。裁决收敛到链尾一处，40100 全站只有一个产出点。

### 2.2 过滤器链的完整裁决逻辑

```mermaid
flowchart TD
    A["HTTP 请求进入"] --> B["SecurityContextHolderFilter（内置）<br/>接管 SecurityContext 生命周期"]
    B --> C["JwtAuthFilter（自定义）<br/>只填充，不拒绝"]
    C --> D{"extractToken 提取 token"}
    D -->|"null：无头 / 非 Bearer 前缀 / 空串"| S["跳过填充，保持现有身份"]
    D -->|"token 存在"| E{"SecurityContext<br/>已有认证信息?"}
    E -->|"有：不覆盖已有身份"| S
    E -->|"无"| F["jwtTokenProvider.parse<br/>验签 + 解析"]
    F -->|"成功"| G["构建 AuthenticatedUser<br/>包装 UsernamePasswordAuthenticationToken<br/>role 补 ROLE_ 前缀"]
    G --> H["身份写入 SecurityContext"]
    F -->|"JwtException / IllegalArgumentException"| I["log.debug 静默降级<br/>token 无效 ≡ 匿名"]
    S --> J["filterChain.doFilter"]
    H --> J
    I --> J
    J --> K["ExceptionTranslationFilter（内置）<br/>异常翻译官，待命"]
    K --> L{"AuthorizationFilter（内置）<br/>链尾守门员"}
    L -->|"有身份且规则满足"| M["Controller<br/>@AuthenticationPrincipal 注入"]
    L -->|"匿名（含 token 无效 / 过期）"| N["拒绝 → 翻译官判定未认证<br/>AuthenticationEntryPoint 写 40100<br/>（HTTP 401）统一响应体"]
    L -->|"已登录但权限不足"| O["AccessDeniedHandler 写 40300<br/>（HTTP 403）"]
```

### 2.3 三个防御性细节

1. **刻意不加 `@Component`**（javadoc L31-33）：加了会被 Spring Boot 当作普通 Servlet Filter 自动注册进容器链，与 Security 链**重复执行一次**，且容器链那次在 `SecurityContextHolderFilter` 之前跑，设进去的认证态随后被覆盖。它由 `SecurityConfig` 手工 `new`，只注册进 Security 链。
2. **已有身份不覆盖**：填充条件是 `token != null && SecurityContextHolder.getContext().getAuthentication() == null`（`JwtAuthFilter.java:54`）。若上游已有过滤器填过身份，本过滤器不抢——防止覆盖别人的成果。
3. **严格校验 Bearer 前缀**（`JwtAuthFilter.java:69-76`）：`extractToken` 对无头、前缀不符、空 token 三种情形一律返回 null，绝不把畸形值送给 `parse`。

### 2.4 角色要补 ROLE_ 前缀

JWT 里存的是业务角色 `USER` / `ADMIN`，而 Spring Security 的 `hasRole("ADMIN")` 实际匹配的是 `ROLE_ADMIN`。包装 authorities 时补前缀（`JwtAuthFilter.java:39-40`、L58）：

```java
List.of(new SimpleGrantedAuthority(ROLE_PREFIX + user.role()))
```

| 测试类 | 用例数 | 覆盖层次 |

### 3.4 未覆盖的部分

1. **「放行」≠「可用」。** `PublicEndpointSecurityTest` 的名单侧只断言匿名请求没被拦成 40100，各接口自身的参数校验与业务逻辑不在此覆盖。
2. **40300 只覆盖了 `hasRole("ADMIN")` 这条路径。** 「非本人操作」那类 40300 由各业务接口在服务层抛出（如笔记删除），不在过滤器链，属各自功能的覆盖范围。
