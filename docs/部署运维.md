# Jotang Note 部署与运维

> 单台阿里云轻量应用服务器上的单体部署：Nginx 托管前端产物并反向代理后端，Spring Boot Jar 交给 systemd，MySQL / Redis / RabbitMQ 三个中间件都走 Docker。发布方式是 git 推送 + 服务器侧构建，不产出本地 jar。

## 1. 目标拓扑

```mermaid
flowchart TB
  H5["浏览器（手机 / PC）"]
  NG["Nginx :80<br/>静态 /var/www/jotang · /api 反代<br/>client_max_body_size 110m"]
  subgraph ECS["阿里云 ECS（Ubuntu24.04，2 核 2G）"]
    APP["Spring Boot Jar<br/>127.0.0.1:8080 · systemd"]
    subgraph DK["Docker"]
      MYSQL[("MySQL 8.4<br/>127.0.0.1:3306")]
      REDIS[("Redis 8<br/>127.0.0.1:6379")]
      MQ[("RabbitMQ 4<br/>127.0.0.1:5672")]
    end
  end
  OSS[("OSS 内网 Endpoint<br/>成都，与 ECS 同地域")]
  H5 -->|HTTP| NG
  NG -->|/api| APP
  APP --> MYSQL
  APP --> REDIS
  APP --> MQ
  APP -->|上传 / 签名 URL| OSS
  H5 -.->|头像直连公网 Endpoint| OSS
```

三个中间件的端口在 compose 里都绑死 `127.0.0.1`，应用通过回环访问；**只有 22 和 80 对公网开放**，3306 / 6379 / 5672 / 15672 / 8080 一律不开。

**当前阶段的约束**：没有域名、没有备案，只能走 `http://<公网IP>`，因此 JWT 与密码是明文传输，**仅限自测**（《概要设计》§1.2 已注明）。以后有备案域名时按 §8 补 HTTPS。

## 2. 内存账（2 核 2G 的现状）

这是本文档最重要的一节。2G 装得下这套东西，但**没有余量**，所有内存相关参数都是被这份账倒推出来的：

| 组件 | 预算 | 由什么控制 |
|---|---|---|
| MySQL 8.4 | ~350–450 MB | `--innodb-buffer-pool-size=128M`（**默认按宿主内存自算，不压会到 400MB+**）、`--performance-schema=OFF` |
| RabbitMQ 4（带管理台） | ~250–300 MB | Erlang VM，基本不可压；管理插件本身也占内存 |
| Redis 8 | ~20 MB | `--maxmemory 128mb --maxmemory-policy allkeys-lru` |
| JVM | ~700–800 MB | `-Xms256m -Xmx512m`，加上 metaspace / 线程栈 / 堆外 |
| 系统 + sshd + systemd + dockerd | ~250 MB | —— |
| **合计** | **~1.6–1.8 GB / 2 GB** | 剩不到 400MB 余量，所以下面两件事是硬要求 |

1. **2G swap 必须配**（§3.1）。它不是用来日常跑的，是构建期和流量尖峰时的保命垫。
2. **构建期必须停掉应用和容器**（§3.6）。`vite build` 打 element-plus 峰值要 1.0–1.5G、`mvn package` 要 600–800M，而三个容器常驻就要 700MB；不停掉的话必然打到 swap 抖动甚至被 OOM Killer 干掉。`update.sh` 已经内建了这一步。

> 想把 JVM 堆调大、或者以后上更大的机器，改 `deploy/systemd/jotang-note.service` 的 `-Xmx` 并重新 `systemctl daemon-reload`。**改动前先按上面的账算一遍**——堆顶穿的表现是整个机器假死，不只是这个应用崩。

## 3. 首次部署

命令里区分两种身份：**root** 做系统级操作（建账号、装软件、写 `/etc`），**jotang** 做构建与发布。下面每段都标了当前该是谁。

### 3.1 基础环境（root）

```bash
apt update 
apt install -y git rsync curl nginx
# Ubuntu 24.04 官方源自带 openjdk-21-jdk-headless

# Node.js 22
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs

# Docker（含 compose v2 插件）
curl -fsSL https://get.docker.com | sh

# JDBC URL 用 Asia/Shanghai，系统时区要与其对齐
timedatectl set-timezone Asia/Shanghai
```

**加 2G swap。** 
Swap 就是交换分区**：拿硬盘空间临时充当内存。2G 内存的机器上这是安全垫，构建期尤其依赖它
```bash
# 创建一个大小 2G 的文件 `/swapfile`，这个文件将作为交换文件。设置只有 root 能读写。
fallocate -l 2G /swapfile && chmod 600 /swapfile
# 把这个文件格式化成 swap 交换文件。立即启用这个 swap。
mkswap /swapfile && swapon /swapfile
# `/etc/fstab` 是开机自动挂载配置文件。添加这行后，swapfile 会在开机时自动挂载。
echo '/swapfile none swap sw 0 0' >> /etc/fstab
# 查看内存（human-readable）确认 swap 已挂载
free -h
```

### 3.2 账号与目录（root）

服务以专用的 `jotang` 系统账号运行，不跑在 root 下：

```bash
useradd -r -m -d /opt/jotang -s /bin/bash jotang  #指定家目录路径为/opt/jotang; 指定登录shell为bash，这个用户可以ssh登录
usermod -aG docker jotang          # 发布脚本要以 jotang 身份跑 docker compose

# 1. /opt/jotang/src：源码目录，存放 git 仓库，用来 `git pull`拉代码、项目构建。
# 2. /var/www/jotang：静态资源目录，前端打包产物，nginx 对外访问，发布时用 rsync 同步覆盖。
# 3. /var/lib/jotang/upload-tmp：上传临时文件目录，后端 multipart 文件上传，用户上传的文件先落在这里。
# 4. /etc/jotang：应用配置目录，存放业务的配置文件（yml/env 等）
mkdir -p /opt/jotang/src /var/www/jotang /var/lib/jotang/upload-tmp /etc/jotang
# 这三处都要让 jotang 能写
chown jotang:jotang /opt/jotang/src /var/www/jotang /var/lib/jotang/upload-tmp
```

`/opt/jotang/src` 是 git 工作区，`/opt/jotang/app.jar` 是构建产物拷出来的位置，两者分开是为了让 systemd 的路径不依赖构建目录结构。

### 3.3 切到 jotang：镜像加速 + 拉代码 + 起三个容器

```bash
su - jotang
```

**国内拉取加速**。这一步不做的话 `./mvnw` 和 `npm ci` 会非常慢。

**必须在真正执行构建的账号下配置**——Maven 读 `~/.m2/settings.xml`、npm 读 `~/.npmrc`，配在 root 家目录里构建时根本看不到：

```bash
mkdir -p ~/.m2
cat > ~/.m2/settings.xml <<'EOF'
<settings>
  <mirrors>
    <mirror>
      <id>aliyun</id>
      <mirrorOf>central</mirrorOf>
      <name>Aliyun Public</name>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
EOF

npm config set registry https://registry.npmmirror.com
```

**还需要为 Docker 配置镜像加速**（root账户下配置）。

```bash
sudo vi /etc/docker/daemon.json
```
填入以下内容：
```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://docker.1panel.live"
  ]
}
```
重载并重启 Docker：
```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```
**拉代码、起 MySQL / Redis / RabbitMQ**：

```bash
git clone https://github.com/ShiwarHoufu/jotang-note.git /opt/jotang/src

cd /opt/jotang/src
cp deploy/.env.example deploy/.env
vi deploy/.env                                    # 填四个强密码
chmod 600 deploy/.env

docker compose -f deploy/docker-compose.prod.yml up -d

exit                                              # 回到 root
```

**数据库和账号不用手工建。** compose 里的 `MYSQL_DATABASE` / `MYSQL_USER` / `MYSQL_PASSWORD` 会在 MySQL **首次启动、数据卷为空时**自动建好库与账号。应用那边 `spring.sql.init.mode=always` 且 `schema.sql` / `data.sql` 全部幂等，首次启动会自动建表并写入学院、课程、标签。

两个容易踩的坑：

- **这三项环境变量只在首次初始化生效。** 之后改 `deploy/.env` 里的值不会同步到已有的库和账号上——要改得进容器执行 SQL，或者删掉数据卷重来（会丢数据）。
- **`MYSQL_USER` / `MYSQL_PASSWORD` 必须与 §3.4 里 `DB_USERNAME` / `DB_PASSWORD` 完全一致**，这是两处配置描述同一个账号。

几个查证命令：

```bash
docker compose -f deploy/docker-compose.prod.yml logs mysql | tail -20
docker compose -f deploy/docker-compose.prod.yml exec mysql mysql -ujotang -p -e 'SHOW DATABASES;'
```

### 3.4 应用环境变量（root）

`deploy/jotang.env.example` 是完整模板，逐项都有注释。装到 `/etc/jotang/jotang.env`：

```bash
cp /opt/jotang/src/deploy/jotang.env.example /etc/jotang/jotang.env
vi /etc/jotang/jotang.env
chown root:root /etc/jotang/jotang.env && chmod 600 /etc/jotang/jotang.env
```

三类必须处理：

1. **必填三项**，缺任一项启动即失败（`JwtTokenProvider` / `OssConfig` 用的是无默认值的 `@Value`）：
   `JWT_SECRET`（`openssl rand -base64 48` 新生成）、`JOTANG_OSS_ACCESS_KEY_ID`、`JOTANG_OSS_ACCESS_KEY_SECRET`
2. **必须与 `deploy/.env` 对齐**：`DB_USERNAME` / `DB_PASSWORD`（对应 `MYSQL_USER` / `MYSQL_PASSWORD`）、`REDIS_PASSWORD`、`RABBITMQ_USER` / `RABBITMQ_PASSWORD`
3. **最容易漏的一项**：`JOTANG_MAIL_RESET_LINK_BASE=http://<公网IP>/reset-password`。它的默认值是 `http://localhost:5173/reset-password`，不改的话重置邮件里的链接用户打不开。

格式注意：**裸 `KEY=VALUE`，不写 `export`、不加引号、行尾不写注释**——systemd 的 `EnvironmentFile` 会把它们原样算进值里。

### 3.5 装 systemd unit（root）

先装 unit、后构建启动——否则 `update.sh` 最后那步 `systemctl start` 会因为没有 unit 而失败。

```bash
cp /opt/jotang/src/deploy/systemd/jotang-note.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable jotang-note      # 只设开机自启，现在还不启动（jar 尚未构建）
```

unit 里 `After=docker.service` + `StartLimitIntervalSec=0` + `Restart=always` 是一组：**三个中间件都在容器里，开机时容器必然比应用起得晚**，应用第一次连不上库会启动失败，靠 systemd 无限重试直到容器就绪。日志只走 stdout，由 journald 接住，没有额外的日志文件要管。

### 3.6 首次构建与启动（jotang）

```bash
su - jotang
cd /opt/jotang/src && bash deploy/update.sh
```

`deploy/update.sh` 做的事：`git pull` → **停应用与容器腾内存** → `bash mvnw clean package -DskipTests` → `npm ci && npm run build` → jar 拷到 `/opt/jotang/app.jar`、dist 同步到 `/var/www/jotang` → `docker compose up -d --wait` → 启动服务。日常发布也是它（§4）。

> 用 `bash mvnw` 而不是 `./mvnw`：仓库在 Windows 上编辑，git 常常不保留 `mvnw` 的可执行位，直接执行会报 `Permission denied`。

脚本里有 `sudo systemctl stop/start`，需要免密授权：

```bash
# 若上一条命令报 sudo 要密码，先退出去加这条规则再重跑
exit
echo 'jotang ALL=(root) NOPASSWD: /usr/bin/systemctl start jotang-note, /usr/bin/systemctl stop jotang-note, /usr/bin/systemctl status jotang-note' > /etc/sudoers.d/jotang-deploy
chmod 440 /etc/sudoers.d/jotang-deploy
```

**不要把整个脚本用 `sudo` 跑**，否则 `target/` 和 `node_modules/` 会变成 root 属主，下次 `git pull` 和 `npm ci` 都会出权限问题。

首次构建在 2 核上大概要 5–10 分钟。验证启动结果：

```bash
systemctl status jotang-note
journalctl -u jotang-note -n 50 --no-pager
free -h    # 关注 available 还剩多少、swap 有没有被大量用掉
```

### 3.7 Nginx（root）

```bash
cp /opt/jotang/src/deploy/nginx/jotang.conf /etc/nginx/sites-available/jotang
ln -sf /etc/nginx/sites-available/jotang /etc/nginx/sites-enabled/jotang
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

配置里有三处与后端是**成对**的，改一个必须改另一个：

| Nginx | 后端 | 关系 |
|---|---|---|
| `client_max_body_size 110m` | `spring.servlet.multipart.max-request-size: 110MB` | Nginx 侧必须 ≥ 后端，否则请求在 Nginx 就被 413 拦下，后端那个上限形同虚设 |
| `proxy_request_buffering off` | —— | 请求体不落 Nginx 临时盘，100MB 的文件直接流给后端 |
| `proxy_pass http://127.0.0.1:8080;` | 接口自带 `/api` 前缀 | **不带尾斜杠、也不 rewrite**。加了尾斜杠会把 `/api` 前缀吃掉，全部 404 |

### 3.8 安全组（阿里云控制台）

入方向规则**只放行 22 和 80**。

排查阶段常有人顺手开 8080、3306、6379、15672，这些一律不要开：应用已通过 `SERVER_ADDRESS=127.0.0.1` 只监听回环，三个容器的端口在 compose 里也绑死了 `127.0.0.1`，公网本来就连不上——开了没有收益，只是多一个被扫的面。

## 4. 日常发布流程

```powershell
# 本地（PowerShell）
git push
ssh root@<公网IP> 'cd /opt/jotang/src && bash deploy/update.sh'
```

`update.sh` 会先停掉应用**和三个容器**再构建（§2 的内存账），构建完再一起拉起来。这意味着发布期间站点完全不可用，时长以构建耗时为下限——2 核上大约 3–6 分钟。这是 2G 机器上换取构建成功率的必要取舍。

## 6. 运维备忘

```bash
COMPOSE="docker compose -f /opt/jotang/src/deploy/docker-compose.prod.yml"

# 看应用日志
journalctl -u jotang-note -f

# 看容器日志
$COMPOSE logs -f mysql        # 同理 redis / rabbitmq

# 重启后端
systemctl restart jotang-note

# 手动导一份数据库（备份还没自动化，见 §7）。用应用账号即可，不需要 root；
# 密码从 deploy/.env 里取，注意 -p 与密码之间不能有空格。
$COMPOSE exec -T mysql mysqldump -ujotang -p"$(sed -n 's/^MYSQL_PASSWORD=//p' /opt/jotang/src/deploy/.env)" \
  --single-transaction jotang_note > ~/jotang_note-$(date +%F).sql

# RabbitMQ 管理台（公网不开 15672，走 SSH 隧道）
ssh -L 15672:127.0.0.1:15672 root@<公网IP>   # 然后本地开 http://localhost:15672
```

**首次上手：造一个管理员账号。** `data.sql` 只种了学院、课程、标签，**没有任何 `user` 行**——《概要设计》§6.2 说的「管理员账号同脚本创建」目前没有对应的脚本。临时办法是先正常注册一个账号，再改角色（`user.role` 默认 `USER`）：

```bash
$COMPOSE exec mysql mysql -ujotang -p jotang_note \
  -e "UPDATE \`user\` SET \`role\` = 'ADMIN' WHERE \`username\` = '<你的账号>';"
```

之后才能访问 `/api/admin/**`（`SecurityConfig` 里要求 `ROLE_ADMIN`）。

## 7. 已知限制

1. **内存没有余量**（§2）。所有参数都是按 2G 倒推的，任何组件想涨内存都要先重新算账。
2. **发布期间站点完全不可用**（§4 停应用+容器再构建），2 核上约 3–6 分钟。
3. **无域名 → 全站 HTTP 明文**，JWT 与密码裸奔，仅限自测。
4. **限频是内存态**。AI 摘要/对话限频、登录失败锁定、重置邮件限频都是 `ConcurrentHashMap`，只在单实例下成立；重启会清空计数。多实例部署时会失效，届时要换 Redis 实现。
5. **登出与改密不会让已签发的 JWT 立即失效**（无状态、无黑名单），token 到期前仍然有效。这是已知取舍，不是部署缺陷。
6. **备份尚未配置**。《概要设计》§6.3 要求的 MySQL 每日 `mysqldump` 还没做，服务器一旦故障数据没有兜底。§6 里给了手工导出的命令。
7. **MySQL 的数据在 Docker 卷里**（`mysql-data`）。它的生命周期跟着卷走：`docker compose down -v` 或手工删卷都会连数据一起删，比裸机 MySQL 更容易误伤。
8. **RabbitMQ 未就绪时应用能否启动未实测**。靠 unit 里的无限重试兜底（§3.5），`update.sh` 里也用 `--wait` 做保障。

## 8. 后续要补的事

- **HTTPS**：有备案域名后，`server_name` 换成正式域名，用 Let's Encrypt 签证书，加上 80→443 跳转与 HSTS。
- **MySQL 每日备份**：`mysqldump` + cron，保留若干天，并考虑异地存一份。注意容器化后要在宿主机上跑 `docker compose exec`，cron 需要能访问 docker。
- **监控内存**：2G 的机器值得加一个简单的内存告警（`free` 或 node_exporter），别等 OOM 才发现。
- **管理员初始化的正式脚本**：把 §6 那条手工 SQL 收敛成可重复执行的初始化脚本，与《概要设计》§6.2 对齐。
- **旧头像清理**（《概要设计》§6.3 里同样标为未落地）。
